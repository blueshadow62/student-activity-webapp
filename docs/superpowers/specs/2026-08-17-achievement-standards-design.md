# 성취기준 연동 설계 스펙

## 개요

교사가 학생 활동을 기록할 때, 담당 과목에 해당하는 2022 개정 교육과정 성취기준을
검색·선택할 수 있도록 한다. 관리자가 최초 설치 시 학교급(초/중/고)을 선택하면,
해당 학교급의 과목 목록과 성취기준이 중앙 시트에 적재된다.

## 데이터 소스

교육부 고시 원문(hwp/hwpx)에서 직접 추출한다. DECK6/korean-secondary-learning-map은
사용하지 않는다.

- 별책5~19: 초·중·고 보통교과 각론
- 별책20~22: 과학·체육·예술 계열 선택 과목
- 별책23~39: 고등학교 전문교과 17개 계열
- 최종 번들 실측: 초등 609개/13과목, 중학 714개/24과목,
  고교 50,678개/794과목(보통교과·계열 선택·전문교과 전체)
- 원문 위치: 교육부 고시 제2022-33호 공식 첨부 별책5~22와
  `D:\2022 개정 교육과정\`의 별책23~39
- 공식 첨부: https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=141&boardSeq=93458

별책2~4는 학교급 총론에서 각론의 코드를 재인용하므로 번들 입력에서 제외한다.
이를 함께 파싱하면 같은 기준이 중복되거나 개정 시점이 섞일 수 있다.

고시문 원문이므로 요약·파생 문구 리스크가 없다. 정부 고시문이라 저작권도 명확하다.

### 성취기준 코드 형식 (파서 주의사항)

두 종류의 코드 형식이 존재한다. 파서는 둘 다 처리해야 한다.

| 구분 | 형식 | 예시 |
|---|---|---|
| 초등·중학·고등 보통교과 | `[학년숫자+과목축약+영역-순서]` | `[2바01-01]`, `[9국01-01]`, `[12화언01-01]`, `[10공국1-01-01]` |
| 고등 전문교과 | `[축약글자 영역-요소-순서]` (공백 포함) | `[성직 01-01]`, `[전일 01-01]`, `[의생 01-01-03]`, `[3개 01-01-01]` |

보통교과 중 공통과목은 과목명에 숫자가 포함된다(`10공국1`, `10공수1`).
좁은 정규식을 쓰면 이들을 놓친다 — 실측에서 299개를 흘린 전례가 있다.

전문교과 코드는 전역 고유키가 아니다. 실제 원문에서 `[전제 01-01-01]`이 서로
다른 과목에 재사용되고, 같은 과목에서도 영역별로 같은 코드가 다른 문장에
재사용되는 사례가 확인됐다. 따라서 내부 식별은 과목·영역·코드·원문 전체를
사용하며, 화면 표시와 검색에만 코드를 사용한다.

## 1. 데이터 파이프라인

### 빌드 스크립트

`scripts/build-standards.js` — Node.js 로컬 실행 (기존 `verify-*.js`와 같은 패턴)

1. 지정 폴더의 별책 hwp/hwpx 전체를 kordoc으로 마크다운 변환
2. 마크다운에서 성취기준 코드+문장+과목명+영역+계열 추출
3. 과목 최상위 제목과 코드 축약을 결합해 학교급·계열별 과목 카탈로그 생성
4. 출력: `StandardsData.gs` — 학교급별 과목 목록과 성취기준을 JSON 문자열 상수로 포함

입력 디렉터리가 나뉜 경우 `--input`을 반복해서 지정하며, 같은 별책 번호는 먼저
지정한 디렉터리의 파일을 사용한다.

### StandardsData.gs 구조

```javascript
const STANDARDS_SUBJECTS = '...'; // [{name, ...}] JSON 문자열
// [{name, abbreviation, schoolLevel, track, category}, ...]

const STANDARDS_DATA = Object.freeze({
  elementary: '...',  // [{code, subject, domain, text, track}, ...] JSON 문자열
  middle: '...',
  high: '...',
});
```

- 초등+중학: 합계 1,323건
- 고등 전체(보통+전문): 50,678건, 생성 파일 전체 약 12.3MB
- 대용량 배열은 전역 초기화 때 파싱하지 않고, 설치·명시적 재적재 시 선택된
  학교급만 지연 파싱한다.
- GAS 프로젝트 50MB 한도의 10-16% — 허용 범위

교육과정이 개정될 때만 빌드 스크립트를 다시 돌린다.

## 2. 중앙 데이터 변경

### 새 시트: `성취기준`

| 열 | 설명 |
|---|---|
| `코드` | `[9국01-01]` 또는 `[전일 01-01]` — 원문 그대로 |
| `과목명` | `국어`, `전기·전자 일반` 등 풀네임 |
| `영역` | 학습 영역명 (있으면) |
| `내용` | 성취기준 문장 원문 |
| `학교급` | `elementary`, `middle`, `high` |
| `계열` | `보통교과`, `전기·전자`, `기계` 등 — 드롭다운 필터용 |

### 새 시트: `과목목록`

| 열 | 설명 |
|---|---|
| `과목명` | 풀네임 |
| `축약코드` | `국`, `전일` 등 |
| `학교급` | `elementary`, `middle`, `high` |
| `계열` | 분류 |
| `과목구분` | `공통`, `일반선택`, `전공일반`, `전공실무` 등 |

### Script Properties 추가

| 키 | 값 |
|---|---|
| `SCHOOL_LEVEL` | `elementary`, `middle`, `high` — 설치 시 설정 |

계열은 시트 데이터에만 있고 별도 Property로 저장하지 않는다. 계열은 필터일 뿐
제한이 아니다.

기존 시트(`학생목록`, `교사담당`, `담당신청` 등)는 변경 없음.

## 3. 설치 흐름 변경

현재: `학교명 입력` → `새 중앙 자료 만들기 / 기존 재연결`

변경 후: `학교명 입력` → **`학교급 선택 (초등학교 / 중학교 / 고등학교)`** →
`새 중앙 자료 만들기 / 기존 재연결`

학교급 선택 시:
1. `SCHOOL_LEVEL` Property 저장
2. 중앙 스프레드시트에 `성취기준`·`과목목록` 시트 생성
3. `StandardsData.gs`에 번들된 해당 학교급 데이터를 두 시트에 일괄 기록

기존 학교 호환: `SCHOOL_LEVEL` 미설정 시 성취기준 기능 없이 기존대로 동작.
관리자 포털에 "성취기준 데이터 설정" 버튼을 두면 기존 학교도 나중에 설정 가능.

## 4. 담당 신청 화면 변경

현재: `<input id="requestSubject">` 자유 텍스트

변경 후: `<input>` + `<datalist>` 검색형 자동완성

- `SCHOOL_LEVEL` 설정된 학교: 과목 목록이 `<datalist>`로 연결됨. 타이핑하면
  과목명이 부분 문자열 매칭으로 필터링
- 고등학교: 상단에 계열 필터 `<select>` 추가. 계열을 고르면 `<datalist>` 내용이
  해당 계열 과목만으로 갱신. 기본값은 "전체"
- "직접 입력" 가능: `<datalist>`에 없는 임의 과목명도 그대로 타이핑해서 제출 가능
- `SCHOOL_LEVEL` 미설정: 기존 자유 입력 그대로

부트스트랩 시 `getAppBootstrapState()`가 `schoolLevel` + 과목 목록을 함께 내려줌.
과목 목록은 수백 건이라 가볍다.

## 5. 활동 기록 화면 변경

### 성취기준 필드 추가

기록 입력 카드: `구분` → `역량` → **`성취기준`** → `내용메모`

- `<input>` + `<datalist>` — 과목 드롭다운과 같은 패턴
- 코드+문장이 자동완성으로 표시 (예: `[9국01-01] 화자의 의도와 관점을 추론하며 듣는다.`)
- 코드나 키워드로 검색 가능
- 선택은 임의 — 비워도 기록 저장 가능

### 로딩 타이밍 — 백그라운드 fetch

1. 교사가 수업(과목)을 선택한 시점에 `google.script.run`으로 성취기준 요청 발사
2. 비동기이므로 UI 블로킹 없음 — 교사는 학생 선택·메모 작성 등을 바로 계속
3. 성취기준 필드를 포커스할 때:
   - 로딩 완료 → 바로 `<datalist>` 표시
   - 아직 로딩 중 → 짧은 스피너 후 표시

### 수업별 성취기준 고정(pin) 기능

- 성취기준을 고른 뒤 "이 수업에 고정" → 개인 `설정` 시트에
  `담당키 → 과목·영역·코드·원문 기반 내부키` 매핑 저장
- 다음에 같은 과목-반 선택 시 고정된 성취기준이 목록 맨 위에 올라옴 (구분 표시)
- 여러 개 고정 가능
- 같은 자리에서 해제 가능

### 시트 열 추가

`활동기록`·`활동기록보관` 헤더에 `성취기준` 열 추가 (기존 `담당키` 뒤).
기존 시트는 접속 시 열이 자동 추가되는 패턴 재사용. 이전 기록은 이 칸이 빈 채로
동작한다.

### 서버 함수

`getStandardsForSubject(subject)` — 과목명으로 중앙 `성취기준` 시트 필터링,
`[{코드, 내용}]` 반환. 과목당 수십~백수십 건. 임의 과목이거나 `SCHOOL_LEVEL`
미설정이면 빈 배열 → 성취기준 필드 숨김.

## 6. 관리자 포털 변경

- `연결 상태` 탭: 학교명 옆에 학교급 병기 (`동아공업고등학교 (고등학교)`).
  학교급 미설정 시 `학교급 미설정` + 설정 버튼
- 관리자가 직접 담당 등록할 때: 기존 `showPrompt()` → 교사 신청과 같은
  검색형 과목 입력으로 교체
- 성취기준 데이터 편집 UI는 넣지 않음 (시트에서 직접 수정 가능)
- 성취기준 데이터 재적재는 설치 초기화 후 재설치로 처리 (기존 패턴)

## 8. 호환성

- `SCHOOL_LEVEL` 미설정 기존 학교: 성취기준 기능 없이 기존대로 동작
  (과목 자유 입력, 성취기준 필드 숨김)
- 기존 기록: `성취기준` 열이 빈 채로 유지, 기존 기능 저하 없음
- 기존 `DEFAULT_SUBJECTS`: `SCHOOL_LEVEL` 미설정 시 폴백으로 유지
- 설치 초기화 시: `SCHOOL_LEVEL`도 함께 초기화
