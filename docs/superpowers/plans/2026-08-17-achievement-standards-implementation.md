# 성취기준 연동 구현 계획

## 목표와 성공 기준

2022 개정 교육과정 원문에서 추출한 초·중·고 성취기준을 학교급별로 설치하고,
교사가 담당 과목과 성취기준을 검색·선택하며 수업별 자주 쓰는 기준을 고정할 수
있게 한다.

다음 조건을 모두 만족하면 완료로 본다.

1. 빌드 스크립트가 초·중·고 보통·전문교과 원문을 처리하고, 완전히 같은 원문
   행만 결정적으로 중복 제거하며 미매칭 문단·과목 없는 성취기준을 발견하면 실패한다.
2. 새 설치는 학교급을 필수로 저장하고 해당 학교급의 `과목목록`·`성취기준`
   시트를 일괄 생성한다.
3. 기존 설치는 `SCHOOL_LEVEL`이 없어도 기존 기능이 유지되고, 관리자 화면에서
   학교급을 나중에 설정할 수 있다.
4. 담당 신청의 과목 입력은 자유 입력을 유지하면서 목록 검색을 지원하고,
   고등학교에서는 계열을 제한이 아닌 필터로만 사용한다.
5. 수업을 선택하면 성취기준을 UI를 막지 않고 백그라운드에서 가져오며 코드와
   문구 키워드로 검색할 수 있다.
6. 성취기준을 비워도 저장할 수 있고, 저장·수정·최근 기록·검색·보관 흐름에서
   값이 보존된다.
7. 교사별 개인 설정에 한 담당키당 여러 성취기준을 고정·해제할 수 있다.
8. 기존 검증 스크립트와 새 성취기준 계약 검증이 모두 통과한다.

## 구현 원칙

- 기존 열의 위치는 바꾸지 않는다. `성취기준`은 `활동기록`과
  `활동기록보관`의 `담당키` 뒤에만 추가한다.
- 임의 과목명과 성취기준 미선택을 계속 허용한다.
- 계열은 과목 목록 탐색용이며 데이터 접근 제한으로 사용하지 않는다.
- 런타임 외부 HTTP 요청이나 새 OAuth 범위는 추가하지 않는다.
- 원문 데이터는 빌드 시 생성하고, 런타임에는 선택된 학교급만 중앙 시트에 쓴다.

## 1. 원문 데이터 빌드

### 변경 파일

- 새 파일: `scripts/build-standards.js`
- 생성 파일: `StandardsData.gs`
- 새 검증: `verify-achievement-standards.js`

### 작업

1. 입력 디렉터리와 출력 경로를 명령행 인자로 받는다.
2. `kordoc`으로 HWP/HWPX를 Markdown으로 변환하되 임시 파일은 OS 임시 디렉터리에
   만들고 종료 시 정리한다.
3. 중복 재인용이 있는 학교급 총론 별책2~4를 제외하고 각론 별책5~39의 제목
   계층, 과목명, 영역명, 코드, 원문 문장을 추출한다.
4. 과목 최상위 제목과 코드 축약을 합쳐 과목 카탈로그를 만든다. 숫자로 시작하는
   전문교과 축약코드(`[3개 01-01-01]`)도 고교 코드로 처리한다.
5. 완전 동일 행 중복, 빈 문장, 과목 매핑 실패, 코드처럼 보이지만 파싱되지 않은
   문단을 검증한다. 공식 원문에 존재하는 코드 재사용은 보존하고 통계로 보고한다.
6. 안정적인 정렬과 JSON 이스케이프를 적용해 `STANDARDS_SUBJECTS`와
   `STANDARDS_DATA`를 생성한다.

### 검증

- 동일 입력으로 두 번 생성한 파일의 해시가 같다.
- 초등·중학·고등 각 데이터가 0건이 아니며 알려진 샘플 코드가 존재한다.
- 완전 동일 내부 식별자 중복, 빈 과목, 빈 본문, 미지원 학교급이 0건이다.
- 생성된 Apps Script 파일을 Node VM에서 읽어 구조를 검사한다.

## 2. 학교급과 중앙 스키마

### 변경 파일

- `InstallationSetup.gs`
- `CentralData.gs`
- `AdminPortal.gs`

### 작업

1. `SCHOOL_LEVEL` 속성과 `elementary|middle|high` 검증·표시 함수를 추가한다.
2. 신규 설치·기존 자료 연결 payload에서 학교급을 필수로 받고 학교명과 함께
   저장한다. 초기화 시 학교급도 제거한다.
3. `과목목록`과 `성취기준` 시트명·헤더를 중앙 스키마에 추가하고 스키마 버전을
   올린다.
4. 학교급 설정 시 번들 데이터로 두 시트를 교체 적재한다. 기존 다른 중앙 시트는
   건드리지 않는다.
5. 기존 설치용 `configureSchoolStandards(schoolLevel)` 관리자 API를 추가해 학교급
   속성 저장과 두 시트 적재를 한 잠금 안에서 수행한다.
6. `getSubjectCatalog()`와 `getStandardsForSubject(subject)`를 추가한다. 후자는 현재
   교사의 활성 담당 과목인지 확인한 뒤 코드·내용·영역을 반환한다.

### 검증

- 학교급 잘못된 값은 저장 전에 거부된다.
- 중앙 스키마 검사에서 두 새 시트의 존재·헤더가 확인된다.
- 같은 학교급 재적재는 두 데이터 시트만 교체하며, 다른 학교급으로의 변경은
  기존 학생·담당 데이터 보호를 위해 새 설치에서만 허용한다.
- 학교급 미설정 기존 설치의 기존 중앙 상태 조회는 계속 동작한다.

## 3. 개인 기록과 성취기준 고정

### 변경 파일

- `Code.gs`
- `PersonalStorage.gs`
- 필요 시 `PersonalRouting.gs`

### 작업

1. `RECORD_HEADERS`와 `PERSONAL_RECORD_HEADERS` 끝에 `성취기준`을 추가하고 기존
   시트 끝 열만 확장하는 마이그레이션을 적용한다.
2. 저장 payload의 성취기준 코드를 선택적으로 정규화한다. 값이 있으면 담당 과목의
   중앙 데이터에 실제 존재하는지 확인하고 `코드 + 문구` 표시값으로 저장한다.
3. 저장·수정·최근 기록·통합 검색 결과에 `achievementStandard`를 포함한다.
4. 개인 `설정` 시트의 독립된 열 블록에 `담당키`, `성취기준코드`, `고정일시`를
   저장한다.
5. 과목·영역·코드·원문 전체로 내부키를 만들어 비고유 코드를 구분하고,
   `getPinnedStandardsForAssignment`, `pinStandardForAssignment`,
   `unpinStandardForAssignment` API를 구현한다. 담당 소유권과 과목 일치를 매번
   확인하고 중복 고정은 멱등 처리한다.

### 검증

- 16열 기존 활동 기록이 17열로 확장되며 앞의 16열 값은 그대로다.
- 성취기준 없음/정상 코드/다른 과목 코드의 저장 계약을 각각 검사한다.
- 한 담당에 여러 코드 고정, 중복 고정, 해제, 다른 담당 접근 거부를 검사한다.

## 4. 설치·과목·성취기준 UI

### 변경 파일

- `Index.html`

### 작업

1. 설치 화면에 학교급 선택을 추가하고 신규·기존 연결 호출에 포함한다.
2. 관리자 연결 상태에 학교급을 표시하고 미설정 시 설정 UI를 제공한다.
3. 부트스트랩/중앙 상태가 반환한 과목 카탈로그로 담당 신청 입력에 `datalist`를
   연결한다. 고등학교에만 계열 필터를 표시하며 입력값 자체는 자유롭게 둔다.
4. 관리자 담당 추가 모달도 같은 과목 카탈로그와 검색 입력을 재사용한다.
5. 활동 기록 편집기에 성취기준 검색 입력, 상태 문구, 고정/해제 컨트롤을 추가한다.
6. 담당 수업 선택 시 `getStandardsForSubject`와 고정 목록 요청을 전역 로딩막 없이
   시작한다. 요청 세대 토큰으로 이전 수업의 늦은 응답을 버린다.
7. 고정 기준을 목록 위에 표시하고 코드나 문구 일부 입력으로 브라우저 검색이
   가능하게 한다.
8. 기록 수정 시 기존 성취기준을 폼에 복원하고 저장·취소 후 상태를 정리한다.

### 검증

- DOM ID, 이벤트 바인딩, 서버 메서드 라우팅 계약을 정적 검사한다.
- 수업을 연속 변경했을 때 이전 요청 결과가 새 수업 목록을 덮지 않는지 검사한다.
- 자유 과목과 성취기준 없는 과목에서 입력 화면이 막히지 않는지 확인한다.

## 5. 회귀 검증과 인수 확인

1. 기존 `verify-v8.4*.js` 전체를 실행한다.
2. 새 `verify-achievement-standards.js`를 실행한다.
3. `git diff --check`와 변경 파일별 diff를 검토한다.
4. 가능하면 테스트용 Apps Script 배포에서 다음을 수동 확인한다.
   - 초·중·고 각각 설치 또는 재설정
   - 고등학교 계열 필터와 타 계열 과목 검색
   - 성취기준 백그라운드 로딩 중 학생 선택·메모 입력
   - 검색, 선택, 저장, 수정, 고정 여러 건, 해제
   - 기존 개인 스프레드시트 자동 확장

## 롤백 단위

1. 생성 데이터·빌드 스크립트
2. 중앙 스키마·설치 API
3. 개인 기록·고정 API
4. 클라이언트 UI

각 단위를 별도 변경 묶음으로 유지해 문제가 생긴 계층만 되돌릴 수 있게 한다.
